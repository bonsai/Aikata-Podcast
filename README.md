# Podcast Agent

AIホストと人間の対話から、3分番組を企画・収録・編集し、音声ファイルとして書き出すWebアプリ。

## MVPのゴール

**テーマを決める → AIホストの台本を作る → AI音声と人間のマイク音声を収録する → 音声を確認・編集する → 完成音声をダウンロードする。**

対象は、個人クリエイターが短い対話番組やインタビューを継続制作するケース。初期版は「AI女性ホスト＋人間の話者」を基本形とし、1エピソード約3分の音声制作に集中する。

## 主要ユーザーフロー

1. **番組・エピソード作成** — タイトル、テーマ、対象リスナー、番組トーンを入力。
2. **構成・台本生成** — 導入、質問、回答メモ、まとめを作成。人間が編集・承認できる。
3. **収録** — ブラウザで人間のマイクを録音し、AIホスト音声を別トラックとして生成・追加する。
4. **編集** — トラックごとに再生し、開始・終了位置の調整や不要部分のカットを行う。
5. **プレビュー・書き出し** — ミックス音声を確認し、MP3（対応できない場合はWAV）をダウンロードする。
6. **保存・再編集** — エピソードと素材の状態を保存し、後から編集・再出力できる。

## MVPの範囲

### 作るもの

- 番組設定とエピソード一覧
- 3分番組の構成・台本編集
- AIホスト音声の生成（TTSプロバイダーを交換可能にする）
- ブラウザのマイク許可、録音、再生、録音のやり直し
- AI音声と人間音声のトラック管理
- 最小限のカット・音量調整・プレビュー
- 完成音声のダウンロード
- 音声ファイルの保存・削除、エラー表示
- 企画・台本・収録素材・書き出し状態の永続化

### MVPでは作らないもの

- Spotify、Apple Podcasts、YouTubeなどへの自動配信
- RSSフィード生成と配信先アカウント連携
- 配信サービスのアナリティクス統合
- リアルタイムの全二重AI音声会話
- 高度なDAW機能、複雑なマルチトラック自動ミキシング
- チーム権限、課金、公開SNS、独自の音声モデル学習

## 技術方針

- **UI:** TypeScript + React
- **API:** Cloudflare Workers + Hono
- **AI:** Workers AIを第一候補に、LLM/TTSはアダプター越しに呼び出す
- **DB:** Cloudflare D1
- **音声保管:** Cloudflare R2
- **ブラウザ録音:** MediaRecorder / Web Audio API
- **デプロイ:** Cloudflare PagesまたはWorkersの静的アセット配信
- **検証:** ローカルで主要フローを確認後、Cloudflareへデプロイ

利用するモデル・TTSプロバイダーは環境変数や設定で切り替え、特定プロバイダーの利用可能性を前提にしすぎない。ブラウザに秘密鍵を置かず、外部APIキーはWorkersのシークレットに保存する。

## エピソードの標準構成（約3分）

| 時間 | パート | 目的 |
|---|---|---|
| 0:00–0:15 | オープニング | テーマと問いを提示 |
| 0:15–0:35 | 導入 | 背景とゲスト／人間話者の立場 |
| 0:35–2:20 | 対話 | 主要質問2〜3問と人間の回答 |
| 2:20–2:50 | 発見・まとめ | 要点、意外な視点、結論 |
| 2:50–3:00 | クロージング | 次回への問い、番組名 |

3分は目標尺であり、初期版では生成・収録後に実時間を表示する。自動で内容を切り捨てず、長い場合は台本を短くする提案を出す。

## エージェント責務

| エージェント | 入力 | 出力・責務 |
|---|---|---|
| Producer | 番組設定・テーマ | 制作状態を管理し、次工程を案内 |
| Planner | テーマ・対象リスナー | 3分の構成、時間配分、質問案 |
| Scriptwriter | 構成・人間のメモ | 編集可能な台本、話者、発話順 |
| Host Voice | 承認済みAIホスト台詞 | TTS音声と生成メタデータ |
| Compliance | 台本・出典・権利情報 | 要確認箇所、事実・引用・権利のチェック結果 |
| Editor | 収録素材・編集指示 | トラック構成、カット情報、完成音声 |
| Exporter | 完成ミックス・メタデータ | ダウンロード可能な音声ファイル |

MVPでは独立した複数エージェントを無理に実装しない。各責務をTypeScriptのモジュール／サービスとして分離し、必要な箇所だけLLMを利用する。最終公開・書き出し前の確認は人間が行う。

## データモデル概要

- `shows`: 番組名、説明、言語、トーン、既定の尺
- `episodes`: 番組ID、タイトル、テーマ、状態、目標尺、作成日時
- `scripts`: エピソードID、バージョン、構成・台本JSON、承認状態
- `assets`: エピソードID、種類、R2キー、MIMEタイプ、尺、サイズ、作成日時
- `tracks`: エピソードID、素材ID、話者、順序、開始位置、終了位置、音量
- `exports`: エピソードID、素材ID、形式、状態、エラー、完了日時
- `compliance_checks`: エピソードID、チェック項目、重大度、根拠、解決状態

具体的なフィールドと状態遷移は [CONTEXT.md](./CONTEXT.md) を参照。

## セキュリティ・プライバシー

- マイク利用前にブラウザの許可を取得し、録音中であることを明示する。
- 録音・AI音声の用途と保存先をユーザーに説明する。
- アップロード、再生、ダウンロード、削除は所有者の権限を確認する。
- R2のオブジェクトキーや一時URLを公開ページに露出させない。
- APIキーをフロントエンドに埋め込まない。
- 素材削除時はDBメタデータとR2オブジェクトの両方を処理する。
- 事実・引用・第三者の音源・声の権利について注意を促し、チェック結果を記録する。

## 受け入れ条件

1. ユーザーが番組とエピソードを作成し、再読み込み後も内容が残る。
2. 3分構成の台本を生成または手入力し、編集して保存できる。
3. マイク録音を開始・停止・再生・やり直しできる。
4. AIホストの音声を生成でき、失敗時は理由と再試行方法が表示される。
5. 人間音声とAI音声を順番に並べ、プレビューできる。
6. 不要区間を除いた音声を作成し、対応形式でダウンロードできる。
7. 音声素材を削除でき、削除済みファイルへアクセスできない。
8. マイク未許可、API失敗、ファイル欠損、書き出し失敗がユーザーに分かる。
9. APIキーをブラウザへ送らず、所有権のないエピソードや素材にアクセスできない。
10. READMEの手順でローカル起動とCloudflareデプロイができる。

## 開発手順

実装タスクは [TASKS.md](./TASKS.md) を参照。まず縦切りの最小機能（エピソード作成→台本保存→人間録音→再生→ダウンロード）を成立させ、次にAIホスト音声、編集、永続化、デプロイの順で拡張する。

## このリポジトリの開発ループ

1. 環境を用意する。
2. 小さく動くアプリを作る。
3. 自分のアイデアをREADMEに書く。
4. 曖昧な要件を問い直し、CONTEXT.mdに決定事項を残す。
5. TASKS.mdでMVPタスクへ分解する。
6. 1タスクずつ実装し、ブラウザ操作・AIレビュー・セキュリティレビューで検証する。
7. GitHubへpushし、Cloudflareへデプロイする。
