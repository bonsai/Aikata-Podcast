# CONTEXT.md — Podcast Agent decisions

## Product decision

- Product: Podcast Agent
- Primary use case: AI host and human co-create a short conversational interview.
- Default format: approximately 3 minutes.
- Recording: AI host audio generated by TTS + human voice recorded through the browser microphone.
- Output: downloadable audio file.
- Deployment preference: Cloudflare-first.
- Primary user: an individual creator producing short episodes.

## MVP user journey

1. Create a show or episode and enter topic, audience, tone, and goal.
2. Generate an editable 3-minute outline and script.
3. Review and approve the script.
4. Record the human voice in the browser.
5. Generate AI host lines through a TTS adapter.
6. Review and arrange both voices as tracks.
7. Make basic cuts and volume adjustments.
8. Preview and export the final audio.
9. Download the output; retain or delete project assets.

## Editorial format

| Time | Segment | Notes |
|---|---|---|
| 00:00–00:15 | Opening | Host introduces the theme and question |
| 00:15–00:35 | Setup | Brief context and human speaker's perspective |
| 00:35–02:20 | Conversation | 2–3 focused questions; human responses |
| 02:20–02:50 | Takeaway | Main insight and summary |
| 02:50–03:00 | Closing | Sign-off and next question |

The runtime is a target, not a reason to truncate speech automatically. Show measured duration and suggest shortening the script when over target.

## Architecture decisions

- Frontend: TypeScript + React.
- API: Cloudflare Workers + Hono.
- Database: Cloudflare D1.
- Audio object storage: private Cloudflare R2 bucket.
- Browser recording and preview: MediaRecorder and Web Audio API where supported.
- AI provider calls happen server-side; secrets are stored in Cloudflare secrets, never in browser code.
- Model, TTS, and audio-export implementations are behind interfaces/adapters.
- The first release should not require a dedicated always-on server.
- Prefer synchronous requests for short operations. Move long-running work to durable/asynchronous execution only when needed.
- Do not assume MP3 encoding is available in every browser/runtime. Verify the encoder; provide WAV as fallback if MP3 is unavailable.

## Agent/service responsibilities

These are logical responsibilities, not a requirement to run seven independent agents.

- Producer: episode state, workflow guidance, handoff between steps.
- Planner: run of show, time budget, interview questions.
- Scriptwriter: speaker turns and editable script.
- Host Voice: TTS generation for approved AI host lines.
- Compliance: flag unsupported factual claims, unattributed quotations, third-party audio/voice rights, and missing disclosure.
- Editor: track ordering, trim points, volume, preview mix.
- Exporter: final encoding, file metadata, download.
- Human creator: approve script, confirm recording consent and rights, review final audio before distribution.

## Data model (logical schema)

### shows
- `id`: string/UUID primary key
- `title`: string, required
- `description`: string, optional
- `language`: string, default `ja-JP`
- `tone`: string, optional
- `target_duration_seconds`: integer, default 180
- `created_at` / `updated_at`: ISO timestamp

### episodes
- `id`: string/UUID primary key
- `show_id`: foreign key to shows
- `title`: string, required
- `topic`: string, required
- `audience`: string, optional
- `status`: `draft | scripting | ready_to_record | recording | editing | exporting | completed | error`
- `target_duration_seconds`: integer, default 180
- `created_at` / `updated_at`: ISO timestamp

### scripts
- `id`: string/UUID primary key
- `episode_id`: foreign key to episodes
- `version`: integer
- `content_json`: structured speaker turns and sections
- `estimated_duration_seconds`: integer, nullable
- `approval_status`: `draft | approved | changes_requested`
- `created_at`: ISO timestamp

### assets
- `id`: string/UUID primary key
- `episode_id`: foreign key to episodes
- `kind`: `human_recording | host_tts | music | effect | mix | export`
- `r2_key`: private object key
- `mime_type`: string
- `size_bytes`: integer
- `duration_seconds`: number, nullable
- `metadata_json`: provider/model, voice label, sample rate, consent and provenance metadata where relevant
- `created_at`: ISO timestamp
- `deleted_at`: ISO timestamp, nullable

### tracks
- `id`: string/UUID primary key
- `episode_id`: foreign key to episodes
- `asset_id`: foreign key to assets
- `speaker`: `human | ai_host | music | effect`
- `position`: integer
- `start_ms` / `end_ms`: integer
- `gain_db`: number, default 0
- `created_at` / `updated_at`: ISO timestamp

### exports
- `id`: string/UUID primary key
- `episode_id`: foreign key to episodes
- `asset_id`: foreign key to assets, nullable until success
- `format`: `mp3 | wav`
- `status`: `queued | processing | completed | failed`
- `error_code` / `error_message`: nullable
- `created_at` / `completed_at`: ISO timestamp, nullable

### compliance_checks
- `id`: string/UUID primary key
- `episode_id`: foreign key to episodes
- `category`: `factual_claim | quotation | music_rights | voice_rights | consent | disclosure`
- `severity`: `info | warning | blocking`
- `message`: string
- `evidence_json`: structured evidence/source references, nullable
- `resolved_at`: timestamp, nullable
- `created_at`: ISO timestamp

## API sketch

- `GET /api/shows`
- `POST /api/shows`
- `GET /api/episodes`
- `POST /api/episodes`
- `GET /api/episodes/:id`
- `PATCH /api/episodes/:id`
- `DELETE /api/episodes/:id`
- `POST /api/episodes/:id/script/generate`
- `PUT /api/episodes/:id/script`
- `POST /api/episodes/:id/tts`
- `POST /api/episodes/:id/exports`
- `GET /api/exports/:id`
- `DELETE /api/assets/:id`

This is a starting contract. Adjust paths to the actual authentication and upload design. Validate inputs and enforce authorization at the API boundary.

## Security and privacy rules

- Do not expose R2 object keys as public URLs.
- Require authorization for every episode and asset operation.
- Use short-lived download links or an authorized download endpoint.
- Set file-size and duration limits for uploaded recordings.
- Ask for microphone permission only when recording is requested and show recording state.
- Provide a clear delete action for recordings and generated audio.
- Keep provider secrets on the server.
- Preserve source recordings when editing; edits should be non-destructive.
- Treat AI-generated claims as unverified until reviewed. Do not invent sources.
- Do not use cloned or identifiable third-party voices without appropriate permission.
- Before sharing or distributing audio, the human creator confirms consent, attribution, and usage rights.

## Acceptance criteria

1. A show and episode can be created, edited, and reloaded without losing saved data.
2. The user can edit and save a structured script with speaker turns.
3. The browser can record, stop, replay, and redo a human recording.
4. Approved AI host text can be sent to TTS and the returned audio can be previewed.
5. Human and AI audio are represented as separate assets/tracks.
6. The user can reorder tracks and set basic trim points and gain.
7. The preview reflects the saved edit plan.
8. A supported output format can be exported and downloaded; failures are visible and retryable.
9. Deleting an asset removes or invalidates both its metadata and stored object.
10. Unauthorized users cannot access another user's episodes, assets, or downloads.
11. No provider secret is included in client bundles or API responses.
12. The core flow works in current Chrome/Edge on Windows, with microphone denial and unsupported codecs handled gracefully.

## Out of scope for MVP

- Direct publishing to podcast platforms, RSS, and analytics integrations.
- Real-time full-duplex voice conversation.
- Advanced DAW features, collaborative editing, subscriptions, and model training.
- Automatic fact verification as a substitute for human review.
