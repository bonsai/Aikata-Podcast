# AI-DLC — Podcast AgentのAI駆動開発ルール

## 目的
AI-DLC（AI-Driven Development Life Cycle）の考え方を要件定義・実装・テスト・運用に適用する。AIに丸投げせず、AIが計画と作業を進め、人間が不明点の解消と重要判断を承認する。本書は本プロジェクト向けの運用文書であり、AWS公式テンプレートそのものではない。

## 基本ループ
**Plan → Ask → Confirm → Execute → Verify → Record**
1. **Plan:** 目的、変更範囲、作業手順、テスト方法を提示。
2. **Ask:** 不明点、前提、トレードオフ、危険な判断を質問。
3. **Confirm:** 人間が重要判断と計画を承認。承認前に不可逆操作や大規模変更をしない。
4. **Execute:** 小さな単位で実装。
5. **Verify:** テスト、ブラウザ操作、差分、セキュリティ、受け入れ条件を確認。
6. **Record:** 決定、根拠、結果、未解決事項をリポジトリに記録。

## 3フェーズ
### Inception — 着想・要件定義
MRD、PRD、MVP、KPI、POCを確認し、課題、ユーザー、非目標、受け入れ条件を整理する。曖昧な点は推測で埋めず質問し、合意内容を文書化してIssueに分解する。

### Construction — 設計・実装・テスト
Kanbanから小さな作業を選び、実装前に計画と変更ファイルを示す。最小の縦切りを実装し、自動テストと手動確認を実行。失敗や制約も記録する。アーキテクチャ、コスト、セキュリティに影響する判断はADR相当の記録を残す。

### Operations — デプロイ・運用
人間の確認後にデプロイする。シークレット、データアクセス、削除動作を確認し、エラー、生成失敗、コスト、書き出し成功率を観測する。ユーザーの反応を次の計画へ戻す。

## Bolt（作業単位）
Boltは数時間〜数日で検証できる小さな作業単位。各Boltに目的、対象範囲、変更予定ファイル、依存・リスク、受け入れ条件、テスト方法、結果・証拠・残課題を含める。「アプリ全体を作る」ではなく「エピソード作成画面と保存API」のように分割する。

## 人間の承認が必要な判断
- MVP範囲・製品目標の変更
- 外部サービス、モデル、音声プロバイダーの採用
- 有料契約や予算増加
- 個人データ、音声保存、利用目的の変更
- セキュリティ境界、認可、公開範囲の変更
- データ削除、破壊的変更、本番デプロイ
- ライセンス、第三者音源、声の権利に関する判断

## 永続コンテキスト
READMEは製品概要、TASKSは実装作業、CONTEXTは決定・データモデル・API、kanban/READMEは進行状態、plan/READMEはStage/Tier/Phase、docs配下は製品・事業・検証方針を記録する。決定変更時はチャットだけで済ませず、関連ファイルを更新する。矛盾がある場合は実装を止め、正とする文書を確認する。

## Definition of Done
- 要求と受け入れ条件を満たす。
- テスト結果を記録し、失敗を隠さない。
- 変更が依頼範囲に沿い、不要な機能が増えていない。
- セキュリティとデータ保護への影響を確認した。
- 関連文書、Kanban、タスク状態を同期した。
- 変更、検証結果、未解決事項を報告する。

## レトロスペクティブ
各Stageまたは大きなBoltの終了時に、完成と証拠、手戻り、AIの誤り、テスト・コスト・セキュリティ上の問題、次に変えることを振り返る。
