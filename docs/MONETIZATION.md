# Monetization — マネタイズ仮説

## 原則
課金機能を先に作らず、制作の継続価値と支払意思を検証する。価格やプランは未確定の仮説。

## 支払対象の仮説
制作時間の短縮、台本・履歴の保存、高品質なAIホスト音声、制作本数や生成量の拡張、テンプレート、複数番組管理、将来のチーム制作機能。

## 収益モデル候補
1. **Freemium + 月額:** 無料枠で体験し、継続利用者が制作本数や高度機能に応じて支払う。
2. **クレジット／従量課金:** 変動費の大きいTTSや生成処理を使用量ベースにする。
3. **買い切り・制作パック:** 定期利用ではない人向けに一定本数やテンプレートを販売する。
4. **B2B・クリエイターチーム:** 教育、イベント、コミュニティ、企業インタビュー用途。需要確認後に検討。

## 仮のパッケージ

| 案 | 価値 | 検証項目 |
|---|---|---|
| Free | 少数エピソードで制作を試す | Activation、完成率 |
| Creator | 継続制作、履歴、多めのTTS利用 | 月額意思、継続率 |
| Studio | 複数番組、チーム共有、ブランド設定 | チーム需要、サポート負荷 |
| Credits | 必要時だけ音声生成・追加出力 | 従量課金の理解、原価 |

価格、無料枠、生成上限は調査と原価計測前に確定しない。

## 原価と粗利
変動費 = LLM費用 + TTS費用 + 音声処理費用 + ストレージ/転送費用 + 決済手数料。
固定費としてサポート、監視、開発、運用を別途把握する。利用上限、タイムアウト、レート制限、再試行制御で無料枠の原価を管理する。

## 検証実験
1. 5〜10名に現在の代替手段と費用を聞く。
2. 月額・クレジット・買い切り案を提示し、選択理由と支払意思を記録する。
3. 手動の有料制作支援やパイロットで実際の支払い行動を確認する。
4. 1本あたり原価を測り、価格と利用上限を調整する。
5. 継続利用が確認できるまでは、決済実装より制作体験を優先する。

## 課金導入の条件
初回書き出しとリピートが計測できる、支払対象を説明できる、原価と利用上限が分かる、解約・返金・税・規約・プライバシーを設計している、支払いと権限のテストがある。

## MVPではやらない
決済、請求、サブスクリプション管理はMVPに含めない。完成音声の価値と継続利用を検証してから収益化方式を選ぶ。
