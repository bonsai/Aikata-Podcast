うん、ここは重要。

この教材でいう **hooks** は「AIが作業する前後に、自動で割り込む仕組み」 のこと。

## ざっくり

```
AIがコードを書く
      ↓
   [Hook]
      ↓
チェック・レビュー
      ↓
OKなら次へ
```

つまり AIに「毎回これやってね」と言わなくても、**強制的に実行させる安全装置**。

## この教材での使い方

特に重要なのが **commit前レビュー**。

```
AIが実装
  ↓
自動Hook
  ↓
テスト・レビュー
  ↓
問題あり → AIが修正
  ↓
問題なし
  ↓
commit
```

なので、

* **CLAUDE.md** → AIへのルール
* **.claude/skills/** → AIに覚えさせる作業手順
* **.claude/hooks/** → AIの行動に自動で割り込む仕組み

という整理でいい。

## 人間でたとえると

**Skill = マニュアル**  
「レビューするときは、この10項目を確認してください」

**Hook = 門番**  
「commitするなら、レビューを通ってからにしてください」

これがかなり違う。

## この教材の思想

Hookの一番おいしいところは、

> **AIを信用するのではなく、AIが間違っても止められる仕組みを作る**

ということ。

だから「AIにコードを書かせる」だけじゃなく、

**AI → 自動チェック → 人間確認 → commit**

までを開発プロセスにする。

個人的には、あなたの今の開発スタイルなら Hookはかなり相性いい。  
特に TASKS.md の1タスクごとに、

**実装 → テスト → レビュー → commit**

を自動化するところが本丸。
